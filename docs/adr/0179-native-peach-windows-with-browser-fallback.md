# ADR-0179：桌面原生主窗口与浏览器回退

## 背景

反馈截图需要记录用户点击时的页面，包括滚动位置、已打开的弹层和浏览器渲染的玻璃侧栏。普通网页截图需要浏览器确认共享。SnapDOM 可以直接生成当前视口的图片，但浏览器的部分合成效果难以重现。

## 决策

- Windows 完成首次设置后，从托盘或 `Peach.exe` 打开同一个本机 Peach 窗口。窗口使用系统已有的 Evergreen WebView2 Runtime，按部署数据目录与本机来源复用。托盘启动不预载窗口。
- Windows 构建携带固定版本的 WebView2 SDK DLL、窗口程序及随附许可。程序按内容写入本机用户缓存，独立于托盘安装目录或临时解包目录。用户配置与浏览器数据分开，WebView2 沿用系统证书验证。
- 点击反馈时打开表单并准备截图。原生窗口先保留反馈遮罩出现前的可见画面，再生成附件。系统运行时、窗口或截图未取得时沿用原入口，网页截图使用 SnapDOM。首次设置继续在默认浏览器里完成。
- macOS 菜单栏和访达重新打开应用时复用 AppKit 中的 WKWebView 窗口。窗口关闭时释放 WebView，菜单栏及服务继续运行。截屏由系统 WebKit 处理，桥接绑定随 `macos` 依赖安装。首次设置和加载失败时打开默认浏览器。
- Docker 只负责提供网页，SnapDOM 在访问者的浏览器里生成截图。浏览器真实截屏需要用户在安全上下文中选择共享来源。容器里的新浏览器会重新加载页面，无法取得访问者当前标签页的渲染状态。

## 影响

首次打开 Windows 窗口会启动独立的 WebView2 进程组。关闭窗口后，托盘和服务照常运行。默认浏览器访问、局域网访问和容器部署不需要安装 WebView2。原生截图附件仍由提交动作统一上传。
