# ADR-0178：同一份内容只验证一次

- 状态：已采纳
- 日期：2026-11-26
- 关系：扩展 [ADR-0151](0151-trusted-ci-test-proof.md) 的受信 CI 证明；[ADR-0172](0172-machine-wide-test-slots.md) 的整机名额与 [ADR-0022](0022-frontend-vite-preact-strangler.md) 的产物提交不变

## 背景

2026-11-14 至 11-25 的 600 次 Test 运行、本机 1,440 次测试运行与同期智能体会话记录显示，返工主要来自三处：

- **同一份内容被验证两到三遍。** 集成先 rebase 再 `--no-ff` 合入，合并提交的内容树就是 PR 头的树。124 次主线 Test 里有 80 次，合并时同一内容树已在 PR 上通过，重复约 10,650 runner 分钟；会话在这之前往往还跑过一轮本机 `auto`。
- **便宜的检查拦得太晚。** 复杂度棘轮、前端 lint、产物不一致等秒级检查让约 50 个 CI 作业变红；文案基线、模块分层等检查排在普通测试之后，20 分钟后才报错。PR 首轮即绿的分支只有 58%。
- **流程自己制造重跑。** 落后主线被 `ready` 拒收后，会话在锁外 rebase 再验证，常被后到先合的任务挤掉；变更日志条目要带 PR 编号，只能开完 PR 再推一次，打断正在跑的 CI；两个改前端的分支必然在 `web/dist` 上冲突。

## 决策

1. **普通改动的正式证明默认取 PR Test。** 本机只跑定向用例和推送前自查（`-Gate`：本次范围里的快速门槛与前端构建、单测），推送后以 `ready --ci-run` 交付。证明或执行协议的逻辑改动、需要本机桌面或真实数据的验收、没有网络时仍用本机 `auto` 或 `full`。
2. **主线合并提交沿用同内容的 PR 证明。** 计划任务按 `ready --ci-run` 的同一套判据核对：同仓库的成功运行、证明里的内容树、协议未改、计划与作业齐全、范围覆盖。通过时本轮只保留计划与汇总任务，运行结论照常作为之后的已验证基线。直接提交、发版提交与内容不同于 PR 头的合并提交照常执行。
3. **落后主线由集成入口处理。** `preflight` 与 `ready` 只报出落后几个提交；`integrate` 取得锁后 rebase、补验并推送。两边都改到的前端产物在 rebase 后照合并的源码重建并补一个提交；按并集合并的变更日志不算需要复核的重叠。源码重叠照旧拒收。
4. **PR 已红不合入。** PR 头上最近一次 Test 已失败时 `integrate` 拒收；仍在运行、被取消、没有运行或取不到时不拦。
5. **变更日志条目可以先不带编号。** 未发布节的条目有 issue 就写 issue；没有时不写，定版时按引入它的主线合并提交补上 PR 编号。`CHANGELOG.md` 按并集合并，重复的分组标题在定版时并成一组。
6. **本机状态不进交付门槛。** 未登记的工作树残留目录由 `create` 报出、`prune` 回收；外层会话注入的 `GIT_CONFIG_*` 在运行器开跑前去掉；新工作树缺前端依赖时入口照锁文件安装。

## 理由

- 内容树相同，验证结论就相同。沿用证明不降低覆盖：核对项与 `ready --ci-run` 一致，协议文件有改动时不沿用。
- 本机记录只覆盖一个平台。11-15 一次 macOS 独有的失败合入主线后，8 个以上分支的 PR 连带失败；PR Test 同时覆盖 Windows 与 macOS。
- 锁内 rebase 之后补验通过就一定合得进去；锁外 rebase 没有这个保证，Claude 侧这类拒收 71 次，从被拒到成功累计约 22 小时。
- 产物是源码的函数，逐行合并两份构建结果没有意义；重建一次得到的才是合并后的那一份，补验里的产物新鲜度检查继续把关。
- PR 编号开了 PR 才有。92 次「取消后再推」里有 27 次只改了变更日志，中位间隔 6 分钟。
- 残留目录、注入的 Git 配置描述的是这台机器，不是被验证的改动；Codex 侧 37 次正式失败里有 16 次只因它们。

## 后果

- 落后主线的分支在 `integrate` 持锁期间补验，后面排队的集成等得更久；等待上限 30 分钟不变，超时后重新发起即可。
- 沿用证明的主线运行没有自己的测试作业，不能再作为别的提交的 `--ci-run` 证明；发版提交是直接提交，照常全量。
- 未发布节的条目在定版前可能没有编号；编号补不出来时定版拒收，交人写。
- `-Gate` 与定向调试一样不签发记录，不能作为 `ready` 的证明。
